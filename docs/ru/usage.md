# Расширенное использование

Аудитория: операторы, которым нужны CLI, ручной импорт, обнаружение или
конкретный формат вывода. Этот документ отвечает на вопрос, как безопасно
использовать эти возможности. Сначала пройдите [краткое руководство](../../README.ru.md#скачать-и-запустить).

Выполняйте команды из папки распакованного релиза. `./routevane` находит
бинарный файл; в Windows при необходимости явно укажите
`./routevane.exe`. Разработчики могут сначала собрать проект по
[английской инструкции](../../CONTRIBUTING.md) и подставить бинарный файл из
`.cache/build/`. Пути к каталогу и данным относительны к текущей папке. Пример
сценария обучения — отдельный [файл](../examples/learning-scenario.yaml), а не
часть архива: сохраните его и укажите его фактический локальный путь.

## Поддерживаемые форматы

Форматы встроены в приложение. Рендеринг и проверка покрываются тестами
репозитория, но это не подтверждает, что физическое устройство или работающий
клиент примет результат.

| Вывод | Использование и предел подтверждения |
| --- | --- |
| Маршруты Keenetic IPv4 | Импорт BAT или доставка на устройство; проверены протоколы, не физический роутер |
| Группы FQDN Keenetic | Импорт через CLI KeeneticOS 5.0+ или доставка; проверены протоколы, не физический роутер |
| Исходный набор правил sing-box | JSON-файл или атомарная доставка в локальный файл; перезагрузка работающего sing-box не проверена |
| dnsmasq nftset OpenWrt | Ручная установка; интеграция с физическим файрволом не проверена |
| Списки адресов MikroTik | Ручной импорт скрипта; выполнение на устройстве и восстановление после прерывания не проверены |
| Список split-tunnel AmneziaVPN | Импорт JSON; принятие файла клиентом не проверено |

Raw JSON — диагностический формат. Ниже описаны требования форматов, ручной
импорт и поведение доставки.

## Основы CLI

Предпросмотр правил без публикации файла:

```powershell
./routevane preview --list example --target raw-json
```

Команда делает живой DNS-запрос с ограничением времени. Вывод стабилен для тех
же нормализованных наблюдений и явного отсечения; ответы DNS и отсечение по
текущему времени между запусками естественно могут различаться.

Обновить, собрать и проверить состояние из CLI:

```powershell
./routevane refresh --list example
./routevane build --target raw-json --list example
./routevane doctor
```

Список также может объявить официальный сетевой источник:

```yaml
sources:
  - id: official-feed
    type: http
    component: web
    config:
      url: https://feeds.example.com/ranges.json
      format: json
```

`format: text` читает один адрес или CIDR в строке и игнорирует комментарии
`#` и `;`. `format: json` принимает простой массив строк либо объект, чей список
`prefixes` содержит строки или объекты с `ip_prefix`, `ipv6_prefix`, `prefix`,
`cidr` или `ip`. Разрешён только HTTPS; адрес назначения, каждый редирект,
размер ответа, число записей и время ограничены. Ненормализуемая запись
пропускается, а не записывается. Префикс из опубликованного оператором источника
принимается; наблюдаемый или выведенный префикс остаётся на карантине.
Если источник не сработал, но его прошлый успех ещё в льготном окне, его
правила сохраняются с предупреждением `source_degraded`.

`refresh` загружает все прямые файлы `catalog/builtin/*.yaml` и
`catalog/local/*.yaml` одним ограниченным снимком до открытия базы или DNS.
`build` печатает абсолютный путь к неопубликованному артефакту в
`data/artifacts/raw-json/<list>/` только после рендеринга в памяти, проверки,
синхронизации файла и атомарной фиксации без замены. `doctor` работает только
на чтение: он не создаёт, не мигрирует, не исправляет и не чекпоинтит базу.

Внутренний планировщик с фиксированной задержкой владеет рекомендательной
блокировкой ОС и запускает одну пару refresh/build одновременно:

```powershell
./routevane run --target raw-json --list example --interval 30m
```

Параметры `--catalog-dir` и `--data-dir` у `refresh`, `build`, `doctor` и `run`
выбирают другие корни. Там, где действуют POSIX-права, режимы файлов и папок
ограничены; Windows `chmod` не считается границей изоляции ACL.

### Подготовленные доменные источники

Поставляемые списки указывают стороннюю подготовку как `community`, а не как
официальную публикацию вендора. `format: domain-list` собирает доменные имена
v2fly, включая помеченные `full:`, и Routevane использует их как суффиксные
правила: указанное имя **и его поддомены**. Это обнаружение назначений, а не
точный перенос исходного набора правил. Шаблоны и удалённые включения не
разворачиваются. `refresh` сообщает `skipped_entries`; карточка списка показывает
число после чтения источника с неподдерживаемыми или неверными строками.

GitHub Copilot отличается от GitHub. Его источник содержит два телеметрических
хоста с меткой `@ads`; Routevane сохраняет эти назначения и не трактует метку
как политику фильтрации. Twitch импортирует только названные CDN-хосты, а не
весь домен `cloudfront.net` или сети провайдера. Kinopub импортирует лишь
поддерживаемые имена: регулярное выражение пропускается, поэтому список не
заявляет покрытие каждого динамического CDN-имени.

## Ручная сборка и импорт файла Keenetic

Обновите каждый список, чьи текущие наблюдения должны попасть в файл, затем
соберите выбранный набор. `--list` можно повторять; значения сортируются и
устраняются дубликаты до одной полностью успешной или неуспешной сборки:

```powershell
./routevane refresh --list youtube
./routevane refresh --list discord
./routevane build --target keenetic --list youtube --list discord --output ./data/artifacts
```

После проверки команда печатает ровно один абсолютный путь `.bat`. Явная папка
вывода должна разрешаться внутри `--data-dir`; без `--output` используется
`data/artifacts`. Неподдерживаемые доменные или IPv6-кандидаты дают
структурированное предупреждение `partial_coverage` только если у каждого
обязательного компонента всё ещё есть безопасное IPv4-правило. Нет нужного
покрытия либо больше 1024 уникальных строк маршрутов BAT — файла не будет.

Перед импортом:

1. Убедитесь, что на роутере KeeneticOS 5.0.4 или новее.
2. Создайте резервную копию конфигурации роутера и сохраните независимый доступ
   для восстановления.
3. Назначьте окно обслуживания: документированный импортёр считается
   добавляющим, его транзакционность и откат неизвестны.
4. Проверьте BAT-файл и число строк маршрутов.
5. Откройте **«Маршрутизация → Пользовательские маршруты → Загрузить»**, выберите
   файл и нужный существующий интерфейс VPN или WAN.
6. После импорта проверьте число маршрутов и убедитесь, что характерные адреса
   списка идут по нужному пути, не теряя доступ для восстановления.

Этот ручной путь не подключается к роутеру, не проверяет его версию или
интерфейс, не применяет файл, не проверяет трафик, не создаёт копию и не
откатывает изменения. Принятие на физическом устройстве **не подтверждено**.

## Фрагмент OpenWrt dnsmasq nftset

Цель `openwrt` создаёт фрагмент конфигурации dnsmasq, а не перечень адресов.
Устройство само разрешает каждый домен и добавляет ответы в набор nftables,
поэтому маршрутизация следует за изменением адресов списка:

```powershell
./routevane refresh --list youtube
./routevane build --target openwrt --list youtube --output ./data/artifacts
```

Фрагмент содержит только суффиксные совпадения. Точный домен отклоняется, а не
приблизительно расширяется: опция dnsmasq совпадает с каждым именем под доменом.

На роутере один раз выполните:

```sh
nft add set inet fw4 routevane4 '{ type ipv4_addr; flags interval; }'
nft add set inet fw4 routevane6 '{ type ipv6_addr; flags interval; }'
```

Добавьте правила файрвола, направляющие элементы этих двух наборов через нужный
интерфейс; затем скопируйте фрагмент в `/etc/dnsmasq.d/` и перезапустите dnsmasq.
Записи остаются в наборе, пока его не очистят, поэтому очищайте оба набора при
удалении списка из профиля. Работа с физическим OpenWrt-устройством **не
подтверждена**; синтаксис опирается на руководство dnsmasq.

## Списки адресов MikroTik RouterOS

Цель `mikrotik` создаёт скрипт RouterOS, заполняющий два списка адресов
файрвола:

```powershell
./routevane build --target mikrotik --list youtube --output ./data/artifacts
```

В отличие от импорта Keenetic, скрипт заменяет содержимое: каждый раздел удаляет
записи, которыми владеет Routevane, а затем добавляет актуальные. Поэтому импорт
нового артефакта приводит к текущему состоянию, а не копит записи. RouterOS сам
разрешает DNS-имя в записи списка адресов, поэтому точный домен передаётся именем;
суффикс отклоняется, потому что запись списка — одно имя, а не шаблон совпадения.

На роутере:

1. Загрузите файл и выполните `/import file-name=<file>`.
2. Используйте `routevane4` и `routevane6` в правиле маршрутизации или mangle,
   которое выбирает нужный интерфейс.

Скрипт очищает только два принадлежащих ему списка. Не переименовывайте их в
список, который вы ведёте вручную. Выполнение на физическом RouterOS-устройстве
и восстановление после прерывания **не подтверждены**; синтаксис следует
документации RouterOS.

## Список сайтов AmneziaVPN для split tunnel

Цель `amnezia` создаёт список сайтов для импорта в клиент AmneziaVPN:

```powershell
./routevane build --target amnezia --list youtube --output ./data/artifacts
```

В клиенте откройте раздельное туннелирование, импортируйте файл из меню и
выберите замену существующего списка сайтов или добавление к нему.

У каждого элемента намеренно пустой список адресов: клиент направляет префикс
сразу, а имя разрешает при поднятии туннеля, поэтому файл не фиксирует адреса,
увиденные при сборке. IPv6 и суффиксные правила отклоняются: иначе клиент
сохранил бы такую запись, не маршрутизируя её. Принятие файла самим клиентом
**не подтверждено**; схема следует его импортёру.

## Локальная служба подписок

Запускатель релиза сам запускает службу. Для прямого запуска бинарного файла
(адрес привязки всегда IPv4 loopback):

```powershell
./routevane serve --port 8765 --catalog-dir ./catalog --data-dir ./data --open-browser
```

Команда печатает принадлежащий серверу origin, обычно `http://127.0.0.1:8765`.
Встроенный интерфейс открывается, когда сервер готов; опустите `--open-browser`,
чтобы открыть его вручную. Создайте профиль, выберите его списки и форматы,
затем обновите и соберите его. UI использует относительные запросы `/v1`.
Изменяющие запросы обязаны иметь точный `Content-Type: application/json` и
`X-Routevane-Request: 1`; сборка никогда не делает скрытое обновление сети.

Добавление формата не создаёт подписку. Первая успешная сборка показывает URL
подписки один раз; первая неудачная сохраняет ограниченную причину и может быть
повторена без потери секрета. Считайте URL bearer-секретом: Routevane хранит
только ID и хеш токена и не может показать его повторно. UI держит его только в
памяти компонента, скрывает до явного показа или копирования и намеренно теряет
после перезагрузки; он не записывает URL в состояние профиля, хранилище
браузера, cookie, кэш или диагностику. Файл скачивается через endpoint ID
артефакта без токена. URL отдаёт независимо проверенные байты с сильным SHA-256
ETag и неизменяемым Last-Modified. Если новый файл отсутствует или повреждён,
служба отдаёт независимо проверенный предыдущий с
`X-Routevane-Fallback: previous`; если не подтверждён ни один, возвращается 503.

Корневой документ и SPA deep links отдают HTML с `no-store`. Хешированные
ресурсы `/_nuxt/` неизменяемы, неизвестные API- и asset-пути остаются 404, UI
использует строгий CSP только для самого себя. Ответ также содержит
`X-Routevane-UI-Digest` для набора встроенных ресурсов. Во время работы нет
Node/Nitro, прокси, CORS-слоя или внешних UI-ресурсов.

`serve` и `run` взаимоисключающие долгоживущие владельцы корня данных. Продукт
остаётся только локальным: удалённая аутентификация, каналы и сборка мусора
артефактов не добавлены.

Выбор устройства показывает все цели каталога, которые может обслужить эта
сборка. Один выбор списков можно опубликовать для каждой: Keenetic получает
диалект IPv4-маршрутов, а `singbox` — исходный набор правил sing-box с
суффиксами доменов, которые формат роутера отбрасывает. Каждый артефакт
проверяется собственным независимым парсером до публикации; имя файла и тип
содержимого задаёт описание рендерера, а не константа.

Результат по умолчанию показывает рабочее состояние, выбранные списки, время
артефакта, тип цели, проверку и предупреждения о частичном покрытии. Формат
артефакта не входит в этот вид: идентификатор и версия рендерера, content type,
свидетельства маршрутизации и исключённые причины видны только в
**«Расширенной диагностике»**. Доступ из LAN/Интернета и отдельные воркеры не
входят в этот локальный релиз. Доставка на устройства, обнаружение браузером и
путь внешних плагинов рендерера/источника есть, но у каждого свои ограниченные
границы безопасности.

## Порядок списков и разрешение пересечений

Порядок выбранных списков определяет, какому списку принадлежит общий адрес. В
профиле перетащите списки в блоке **«В профиле»**: выигрывает тот, что стоит
выше. После сохранения этот порядок закрепляется за профилем, а его выводы
пересобираются. Изменение приоритета по умолчанию в разделе **«Списки»** влияет
только на начальный порядок новых профилей и прогнозов; уже созданные профили
оно не меняет.

Если два выбранных списка содержат одинаковое назначение, Routevane оставляет
его в списке с более высоким приоритетом. Более узкое правило из нижнего списка,
целиком покрытое верхним, исключается. Более широкая сеть из нижнего списка
сохраняется, если в ней остаются адреса, которых нет в верхнем списке, поэтому
перестановка приоритета не уменьшает запрошенный охват маршрутизации. Новый
участник живой категории добавляется после сохранённого порядка профиля.

У выбранных строк теги пересечений называют все остальные выбранные списки, с
которыми они пересекаются. По ним можно решить, какой список поднять выше, не
редактируя сотни отдельных адресов. Сводка в тегах полная, даже если в
**«Диагностике»** показаны только первые 100 подробных записей.
Точные правила владения описаны в [ADR 0036](../adr/0036-route-local-list-priority.md).

## Перенос конфигурации на другой компьютер

На исходном компьютере откройте **«Настройки → Перенос конфигурации»** и скачайте
JSON-файл. В новой установке Routevane выберите этот файл, проверьте состав в
предпросмотре и примените перенос. Установка-получатель должна быть пустой:
перенос не объединяется с уже созданными профилями, подключениями или списками.

Текущий файл `config-transfer-v1.4` включает общий период обновления, приоритет
списков библиотеки по умолчанию, пользовательские списки и категории, включение
и выключение источников каталога, ручные исправления адресов, профили с их
собственным приоритетом, несекретные данные подключений и привязки форматов.
Паролей роутеров,
секретов подписок, адресов добавленных пользователем HTTP-источников,
опубликованных файлов, наблюдений, истории, резервных копий, журналов и настроек
браузера в нём нет. Если такие источники были пропущены, предпросмотр об этом
предупредит; после переноса добавьте их заново. Локальные списки из
`catalog/local` тоже не переносятся: на другом компьютере этих файлов может не
быть.

После импорта заново введите пароли устройств, опубликуйте каждый формат, чтобы
создать новый файл и подписку, и только потом включите нужную автоматическую
доставку. У импортированных устройств она всегда выключена. Предпросмотр и
применение проверяют один и тот же хеш файла; изменённый или заменённый файл надо
проверить заново. Файл, выгруженный прежней версией, по-прежнему
импортируется: поля, переименованные в ADR 0039, читаются под прежними
именами одну минорную версию. Файл, где одно поле указано сразу под двумя
именами, отвергается. Это перенос настроек, а не резервная копия базы данных. Подробный
контракт описан в [`ADR 0033`](../adr/0033-portable-configuration-transfers.md).

## Добавление списка по URL

```powershell
./routevane discover --url shop.example.co.uk
```

Первый вызов не загружает страницу браузером. Он печатает канонический HTTPS
URL, регистрируемый домен по Public Suffix List и локальный идентификатор списка,
который он создал бы. Повторите с `--confirm`, чтобы запустить именно этот URL:

```powershell
./routevane discover --url shop.example.co.uk --confirm --list-id shop --title Shop --browser "C:/Program Files/Google/Chrome/Application/chrome.exe"
```

Одна управляемая загрузка страницы выполняется в изолированном временном профиле,
удаляемом при успехе, ошибке и отмене. Каждый запрос идёт через внутренний прокси,
который отказывает этому компьютеру и локальной сети; число запросов, хостов,
байтов и время ограничены. Хосты под регистрируемым доменом введённого сайта
настроены для наблюдения; все прочие показываются кандидатами и никогда не
активируются. Черновик записывается в `catalog/local/<id>.yaml`, содержит только
домены и никогда не заменяет существующее определение. Наблюдаемые адреса
остаются в локальной базе.

Для обнаружения нужен уже установленный Chromium-совместимый браузер; замените
пример пути Windows фактическим исполняемым файлом вашей ОС. Его задают
`--browser PATH` или `ROUTEVANE_BROWSER`; относительный путь или имя файла
без пути отсчитывается от текущего каталога, поиск по PATH не используется.
Node.js и Playwright во время работы не нужны.

## Обучение списка по сценарию исследования

Одна загрузка страницы не видит всё, что находится за входом или кнопкой
воспроизведения. Сессия обучения воспроизводит описанный сценарий и привязывает
увиденное к действию, которое к нему привело:

```powershell
./routevane learn --scenario learning-scenario.yaml
./routevane learn --scenario learning-scenario.yaml --confirm --browser "C:/Program Files/Google/Chrome/Application/chrome.exe"
```

Вместо управления браузером можно импортировать захваченный архив:

```powershell
./routevane learn --har session.har --url app.example.co.uk --confirm
```

Оба пути дают одинаковые свидетельства и детерминированные решения. Хост того же
сайта, отнесённый к обязательному пройденному компоненту, активируется.
Телеметрия и реклама записываются, но никогда не активируются. Компонент без
пройденного шага ничего не добавляет, а каждый хост за пределами регистрируемого
домена остаётся зависимостью. В определении для каждой пройденной области есть
один компонент; происхождение сессии хранится в связях `loaded_by`,
`redirects_to` и `observed_in_session`, которые никогда не влияют на
маршрутизацию. Читаемый документ со свидетельствами записывается под корнем
данных.

## Применение артефакта к устройству

Локальный экран может сделать это за вас. Если ответ об отправке потерян,
состояние **«Результат неизвестен»** предлагает **«Проверить результат»** той же
попытки. Файл повторно не отправляется. Записанный результат сохраняется после
перезапуска сервиса. Если сервис аварийно завершился до записи результата,
состояние остаётся неизвестным: перед новой доставкой нужно проверить устройство.

Ниже приведён эквивалент в CLI, где пароль читается из переменной окружения,
а не из формы.

Автоматическая доставка добровольна и не требуется: ручное скачивание работает
как прежде. Если нужна доставка, пароль устройства задаётся переменной окружения,
а не флагом:

```powershell
./routevane deploy --artifact ID --target keenetic --device http://192.168.1.1 --user admin --interface Wireguard0
$env:ROUTEVANE_DEVICE_PASSWORD = Read-Host -AsSecureString | ConvertFrom-SecureString -AsPlainText
./routevane deploy --artifact ID --target keenetic --device http://192.168.1.1 --user admin --interface Wireguard0 --confirm
```

Первый вызов ничего не меняет. Подтверждённая доставка проверяет прошивку,
отказывает несовместимому устройству до изменений, создаёт и проверяет резервную
копию конфигурации, сверяет точные сохранённые права Routevane на маршруты и
читает таблицу маршрутов обратно. Если доставка или проверка не удалась,
восстанавливается копия. Чужие и существовавшие до Routevane маршруты сохраняются
даже на том же интерфейсе. Общий адрес удаляется только после того, как он больше
не нужен ни одному выводу; без истории владения Routevane может лишь добавлять и
не пытается угадать права по имени интерфейса. Повторная доставка ничего не
меняет.

У созданного Routevane маршрута поле **«Описание»** имеет вид
`(категория/список)`. Для списка без категории используется
`(Без категории/список)`. Если один адрес пришёл из нескольких списков, после
первой по алфавиту метки добавляется `+N`, а полный набор остаётся в снимке
плана. После записи Routevane читает описание обратно и откатывает изменения,
если Keenetic его пропустил или изменил. Описание готового маршрута с тем же
адресом не трогается. Скачиваемый BAT-файл остаётся прежним: описания добавляются при
автоматической доставке через RCI.

Каждый шаг записывается с результатом и длительностью; учётные данные не попадают
в запись. Подробности: [ADR 0032](../adr/0032-persist-exact-keenetic-static-route-ownership.md)
и [ADR 0034](../adr/0034-keenetic-route-descriptions-from-plan-provenance.md).

Откат Keenetic загружает полный захваченный конфиг, а не разницу маршрутов.
Избегайте параллельных изменений роутера: посторонние изменения после копии
тоже могут быть отменены. Успех отката требует сохранения и повторного чтения
восстановленной конфигурации; отказ сохранения или несовпадение даёт
`rollback_failed`. Восстановление на физическом устройстве не проверено.
Используйте ID интерфейса, например `Wireguard0`, а не его описание. Для
DNS-доставки до сверки отклоняется исключительная (`reject=true`) или
неоднозначно привязанная группа Routevane; отсутствие `reject` или
`reject=false` допустимо. Для собственных привязок Routevane восстанавливает и
проверяет `auto=true`; этот флаг задаёт политику, а не подтверждает связность
интерфейса.

Владение группами Keenetic DNS относится к точному выводу и адресу устройства.
Новые сборки используют имена `<префикс>-<хеш вывода>-<хеш списка>-s<номер>`.
В настройке вывода можно задать префикс FQDN-групп (по умолчанию `routevane`):
до 24 строчных латинских букв, цифр и дефисов, с буквой в начале и без дефиса
в конце. Сохраните настройку и соберите вывод снова. Опубликованные файлы
остаются неизменными. Предпросмотр отправки читает роутер без записи и показывает
точные команды, включая удаление старых имён, записанных за этим выводом.

Префикс не доказывает владение. Неизвестные группы, в том числе старые
`routevane-*` и группы другого вывода, сохраняются. Если нужное имя существует
без подтверждённого владения, доставка останавливается с
`fqdn_ownership_conflict`: проверьте группу и перенесите её вручную на роутере,
затем повторите отправку. Потеря или закрытие локальной истории владения не
разрешает автоматическое присвоение групп. Прерывание доставки до записи этой
истории может потребовать такой же ручной проверки. Подробности:
[ADR 0040](../adr/0040-exact-fqdn-output-ownership.md).

Для доставки без участия человека зарегистрируйте устройство в разделе
**«Подключения»**, указав все несекретные поля, которые запрашивает доставщик
(для Keenetic — интерфейс маршрутов), затем включите автоматическую доставку.
Пароль роутера хранится только в хранилище учётных данных ОС; локальной цели,
такой как sing-box, пароль не нужен и запись учётных данных не создаётся. На
вкладке **«Подключение»** профиля привяжите соответствующий вывод к этому
явно выбранному устройству и выберите ежедневное или еженедельное обновление.
После этого планировщик:

1. обновляет профиль и независимо пересобирает каждый вывод;
2. рассматривает только артефакт, успешно опубликованный в том же запуске;
3. доставляет его лишь явно привязанному и согласившемуся устройству;
4. применяет тот же цикл проверки, совместимости, резервной копии, доставки,
   проверки и отката, что и ручная отправка.

Неудачный формат не доставляется из старого файла; ошибка одного устройства не
останавливает соседние выводы, а ранее опубликованный артефакт остаётся доступен.
Отключение автоматической доставки удаляет сохранённые учётные данные; забывание
устройства отвязывает его от выводов, не удаляя их файлы или подписки, и
закрывает прежнюю область владения маршрутами без изменений на роутере.

Интерфейс Keenetic RCI, включая поле `comment` маршрута, не описан спецификацией
производителя. Поэтому доставщик проверен на точном двойнике устройства и **не
принят на физическом роутере** в среде этого репозитория. Он отказывает там, где
не может подтвердить состояние, вместо догадки.

## Применение набора правил к локальному sing-box

Цель `singbox` может применяться к установленному на этом компьютере sing-box.
Назначение — файл, объявленный вашей конфигурацией:

```json
{
  "profile": {
    "rule_set": [
      { "tag": "routevane", "type": "local", "format": "source", "path": "routevane.json" }
    ]
  }
}
```

```powershell
./routevane deploy --artifact ID --target singbox --device file:///C:/sing-box/config.json
./routevane deploy --artifact ID --target singbox --device file:///C:/sing-box/config.json --confirm
```

Локальная доставка не принимает учётную запись, интерфейс или секрет; передача
любого из них отклоняется, а не игнорируется. Жизненный цикл такой же, как для
устройства: проверка, копия, доставка, проверка и откат при ошибке. Копия
содержит прежний набор правил, в том числе факт его отсутствия, поэтому откат
восстанавливает точно прежнее состояние.

Конфигурация без локального исходного набора правил отклоняется до изменения
файлов. Проверка доказывает, что файл на диске совпадает с опубликованным
артефактом и проходит валидатор sing-box; она **не** доказывает, что работающий
sing-box его перечитал. После доставки перезапустите или перезагрузите sing-box.
