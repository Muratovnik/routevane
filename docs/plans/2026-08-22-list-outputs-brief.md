# Бриф: интерфейс модели «список + выводы»

Основание: ADR 0013 (модель) и ADR 0014 (учётные данные устройства). Решения
владельца от 2026-08-22 в двух раундах.

Реализовано целиком: списки и выводы (729f4d9); категории, ссылки, исключения
и дедупликация на выводе (4471817, ADR 0016); домены и класс `community` в
фиде плюс схлопывание префиксов (fa7a4b7); цель `keenetic-dns` с делением на
подгруппы (da85bfa, ADR 0017); каталог из 49 сервисов в 13 категориях
(13152f4, ADR 0015); расписание (10f4626); устройства и хранение учётных
данных в системном хранилище (73dabba, ADR 0014); архивация списков
(ADR 0018).

## Модель объектов

Основание — ADR 0016 (категории и ссылки) поверх ADR 0013.

- **Список** — единица хранения и выгрузки: имя + свои записи + ссылки на
  категории и поставляемые списки + исключения. YouTube — список; набор,
  собранный пользователем, — тоже список. Ссылаться можно только на каталожное:
  список не ссылается на другой пользовательский список, поэтому циклы
  невозможны по построению.
- **Категория** — именованная группировка списков, many-to-many. Своих данных
  не держит. **Пресет — это категория, которую поставляем мы**; взять пресет
  значит сослаться, а не скопировать.
- **Вывод** — формат (+ опционально устройство) поверх любого набора: одного
  списка, нескольких, категории, нескольких категорий. Владеет своей ссылкой
  подписки и историей версий артефактов. Файл выдаётся только через вывод.
- **Дедупликация — на выводе.** При сборке ссылки разворачиваются в один
  плоский набор, исключения снимаются, дубли схлопываются, и только потом
  строится план. Discord, доступный через «Общение» и «Игры», уезжает на
  устройство один раз и бюджет тратит один раз.
- **Устройство** — зарегистрированный вручную экземпляр цели каталога: имя,
  адрес, учётные данные, автоотправка.

Следствие для диагностики: переполнение бюджета относится к набору, а не к
последнему добавленному списку. Сообщение называет набор и вкладчиков.

## Разделы

1. `/` — **Списки.** Строка: имя, состав, выводы, время содержимого.
   Первичное действие — открыть список.
2. `/lists/new` — **Новый список.** Пресеты сверху, ниже поиск и чипы по
   сервисам. Цель не спрашивается. Имя предложено и правится, обязательного
   ввода нет.
3. `/lists/{id}` — **Список.** Имя и состав редактируемые; вкладки
   Обзор · Выводы · Диагностика.
4. `/devices` — **Устройства.** Регистрация экземпляров поверх каталога целей.
   Заменяет нынешний read-only экран «Цели».
5. `/settings` — **Настройки.** Как сейчас + интервал обновления по умолчанию.

## Состав списка на экране

Гибридный список показывает происхождение каждой строки: из подборки,
добавлено вами, исключено вами. Исключённое остаётся видимым отдельной группой
с возможностью вернуть — иначе человек не понимает, почему подборка «неполная».
Когда подборка пополняется, состав меняется сам, а в истории списка появляется
запись «подборка добавила X»; это не уведомление-модалка и не требует
подтверждения. Переключатель следования отражает фактическое состояние: пока он
включён, список продолжает получать пополнения даже после исключений.

## Выводы у списка

Таблица: формат, устройство (если есть), текущая версия, время, действия
(скачать, отправить, ссылка подписки, содержимое файла). «Обновить и
пересобрать» — действие списка, затрагивает все его выводы.

Пока устройств ноль или одно, страница списка не заставляет ходить во вкладку
«Выводы»: действия «Скачать …» и «Отправить» стоят прямо на странице и
работают через единственный вывод. Вкладка существует всегда, но обязательной
становится при нескольких выводах.

## Расписание

В настройках — интервал по умолчанию (выключено, сутки, неделя), по умолчанию
выключено. У списка — свой интервал, перебивающий глобальный, со значением «как
в настройках» в качестве исходного. Список показывает, каким правилом он
обновляется и когда обновлялся в последний раз.

Неудачное автообновление помечает список и ждёт следующего тика: предыдущий
файл остаётся живым, повторов внутри одного тика нет.

## Устройства и учётные данные

Добавление вручную: выбрать цель из каталога, задать имя и адрес. Сетевого
обнаружения устройств нет.

Экран `/devices` показывает зарегистрированные устройства, а ниже — каталог
поддерживаемых форматов, экземплярами которых они являются. Это один экран, а
не два: каталог перестал быть отдельным разделом «Цели».

Автоотправка у устройства выключена. Включение прямо говорит, что учётные
данные будут сохранены в хранилище учётных данных операционной системы, пока
автоотправка не выключена (ADR 0014). Тумблер встаёт во включённое положение
только после того, как хранилище приняло секрет. Выключение удаляет запись, и
неудача удаления показывается ошибкой. Без автоотправки поведение прежнее:
пароль живёт одну попытку.

## Миграция и бэкенд

- Каждый существующий профиль → список + один вывод с его целью, подпиской и
  историей артефактов. Ссылки подписки продолжают работать, токены не
  ротируются (ADR 0004).
- API: списки CRU (без D), выводы create/list, устройства CRUD, пресеты в
  каталоге, расписание. Пагинация — серверный LIMIT, без query-строки.
- Иммутабельность `plan_snapshots` / `artifact_builds` не меняется.
- Планировщик уже живёт внутри процесса; расписание списков — его второй
  потребитель, а не новый бинарник.

## Каталог: списки и категории

Решено 2026-08-22, основание — ADR 0015 и ADR 0016. Публичные списки берутся
как сырьё: списки и категории наши, ни один источник не копируется один в один.

**Поставляемые списки — по одному на сервис.** У списка может быть несколько
источников: суффиксы доменов от itdoginfo и v2fly, подсети от
iplist.opencck.org. Дубли схлопываются, планировщик решает, что нужно
конкретной цели.

**Домены берём суффиксами, не перечислением хостов.** Цель, которая сама
разворачивает поддомены, требует суффиксной формы; перечисление раздувает
результат на порядки. Замерено 2026-08-22:

| YouTube как… | Записей |
|---|---|
| суффиксы (itdoginfo) | 18 |
| суффиксы (v2fly) | 178 |
| CIDR (iplist, схлопнутые) | 786 |
| перечисленные хосты (iplist `data=domains`) | 15 312 |

Остальные в суффиксной форме того же порядка: Discord 20/28, Telegram 20/21,
Meta 11/18, TikTok 36, Netflix 28, OpenAI 23. Поэтому iplist — источник только
адресов, домены идут от itdoginfo и v2fly.

**Категории — по занятию, а не по источнику.** Список входит в сколько угодно
категорий; копий не возникает, дедупликация происходит на выводе.

| Категория | Списки |
|---|---|
| Видео | YouTube, TikTok, HDRezka, Netflix, Lostfilm, Filmix, Stremio, Kinozal |
| Общение | Telegram, Discord, Signal |
| Соцсети | Meta, X, LinkedIn, Snapchat |
| ИИ-ассистенты | ChatGPT, Claude, Google AI, Grok, DeepSeek, Perplexity, Copilot |
| ИИ-инструменты | DeepL, Grammarly, Canva, ElevenLabs, NotebookLM |
| Музыка | Spotify, Deezer, Tidal, SoundCloud, Last.fm |
| Работа | Notion, ClickUp, Miro, Zapier, Proton, Basecamp, Medium |
| Разработка | JetBrains, Sentry |
| Игры | Roblox, Discord, itch.io, Nexus Mods, Modrinth, Chess.com |
| Торренты | Rutracker, NNM-Club, Rutor, 1337x, TPB |
| Инфраструктура | Cloudflare, Cloudfront, DigitalOcean, Hetzner, OVH |

Discord входит и в «Общение», и в «Игры» — это ровно тот случай, ради которого
категории заменили копируемые пресеты.

Категорийные файлы источников (anime, news, porn и прочие) не импортируются:
категория, внутрь которой нельзя заглянуть и отредактировать, — это подборка,
притворяющаяся сервисом. `news`, `porn` и `casino` из iplist не поставляем —
решение владельца, не техническое ограничение.

Реестр РКН из 1andrevich подключается только пересечением с доменами наших
списков; остальные 81 тыс. записей не импортируются.

## Цели Keenetic

Основание — ADR 0017. Целей две.

- `keenetic` — BAT со статическими маршрутами IPv4, до 1024 строк. Для прошивок
  до 5.0 и для наборов, где домены не нужны.
- `keenetic-dns` — `object-group fqdn` + `dns-proxy route` для KeeneticOS 5.0+.
  Суффиксы доменов и адреса. Список сверх `max_entries_per_list` делится на
  подгруппы `<имя>`, `<имя>-2`, `<имя>-3` — это дело адаптера, пользователь
  видит один список. Все подгруппы лежат в одном файле, модель публикации не
  меняется.

Имена подгрупп несут наш префикс: 128 групп — общий ресурс устройства, и мы
никогда не пишем имя, которое не создавали. `max_lists` тратится на устройство
целиком, а не на вывод; при переполнении сборка отказывается и называет бюджет.

Отправка на устройство согласует состояние (ADR 0019): читает то, что мы писали
раньше, удаляет группы и записи, которых в артефакте больше нет, добавляет
недостающее и привязывает каждую группу к названному интерфейсу. Владение —
ровно префикс `routevane-`; чужая группа и чужой `dns-proxy route` невидимы.
Ручная вставка файла добавляет и обновляет, но не удаляет: файл не знает, что
уже лежит на роутере, а удаление группы забрало бы с собой привязку оператора.

Числа лимитов живут в профиле цели как данные. Документировано: 1024 строки
BAT, 128 object groups (строка из changelog 5.0 Alpha 1, до появления
FQDN-групп). Предел записей в группе не документирован нигде; берём своё
значение и записываем его происхождение.

Два требования к устройству — забота пользователя, мы их только называем: на
5.0 и 5.1 DNS-маршрутизация работает лишь с политикой Default, и клиент должен
использовать роутер как DNS.

## Архивация

Список можно перевести в архив: он уходит из основного вида и перестаёт
обновляться, но его файлы и подписка продолжают работать. Удаления нет
(ADR 0004).

Что значит «перестаёт обновляться», уточнено в ADR 0018: архивный список
заморожен, и единственная запись, которую он принимает, — возврат из архива.
Правка состава, расписание, добавление формата, обновление и пересборка
отклоняются с 409; таймер пропускает такой список до того, как решит, что он
просрочен, поэтому неудачное обновление ему не приписывается. Чтения не
затронуты: файл скачивается, подписка отдаёт ровно те байты, с которыми список
ушёл в архив.

Из основного вида — не из библиотеки. Архивные списки лежат под одним
раскрытием на том же экране, с датой ухода и ссылкой на файл: строка, которая
исчезла бы совсем, оставила бы человека с работающей подпиской, которую негде
найти.

## Порядок работ

Пройден полностью в этом порядке: категории и ссылки → источники (домены и
класс `community`) → цель `keenetic-dns` → наполнение каталога → расписание →
устройства и учётные данные → архивация. Каталог шёл после источников и цели
намеренно: без доменов в фиде и без доменной цели наполнять его было нечем и не
для чего.

## Что не делаем сейчас

Удаление списков и артефактов (ADR 0004); сетевое обнаружение устройств;
живой статус «роутер забрал подписку» без записанного сервером факта;
категории, создаваемые пользователем; произвольная вложенность списков
(ADR 0016); многочастные артефакты для BAT-цели (ADR 0017).
