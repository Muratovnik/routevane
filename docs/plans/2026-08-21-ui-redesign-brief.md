# Проект нового интерфейса Routevane

> Superseded 2026-08-21: модель «три экрана-шага» заменена модульной
> библиотекой списков (разделы Списки / Цели / Настройки, объект «список» с
> вкладками и действиями). Действующая система описана в корневом `DESIGN.md`.
> Актуальным остаётся раздел 7 — бэкенд-бэклог: живой статус «роутер забрал
> подписку» (`last_polled_at`), regenerate ссылки, список интерфейсов из probe,
> история сборок.

Дизайн-бриф. Спроектирован с нуля, не отталкиваясь от текущей страницы;
текущий UI — анти-референс (доказательная база: `docs/audits/2026-08-21-ui-critique.md`).
Направление закреплено пользователем: категорийный стандарт операционной
консоли по интерфейсным референсам Codex-look; без визуальных
метафор. Результат задачи — этот проект; реализация — отдельная задача.

## 1. Задача и аудитория

Любой человек — от новичка («хочу, чтобы Discord работал») до power user с
несколькими устройствами. Пользователь сам выбирает уровень вовлечённости:
интерфейс живёт в двух режимах. Локализация RU/EN — равные случаи вёрстки.
Режим поверхности — Operate: пользователь выполняет задачу, выразительность
никогда не заслоняет состояние и действие.

## 2. Результат и доказательство

Первичная задача: выбранные сервисы работают через нужный интерфейс роутера,
и пользователь этому верит, потому что видел, что именно уехало на устройство.
Доказательства встроены в путь: превью содержимого артефакта дословно,
живой статус «роутер забрал подписку», аудит шагов применения с откатом.

## 3. Выбранное направление

**Интерфейсный стандарт, исполненный в полную силу.** Референсы и планка:

- **Референсная операционная консоль:** near-black консоль,
  зоны chrome/workspace, статус всегда «точка + текстовая метка», никогда
  заливка поверхности; одна светлая primary-кнопка на экран; плотность через
  выравнивание; типографическая шкала 12→28px с полом чтения 13px; моно для
  всего, что сравнивается посимвольно.
- Линия происхождения — консоль Codex/ChatGPT (#181818 canvas, #212121
  surface, ступени hover/active).
- Сетевые инструменты — уровень Tailscale admin console (эхо идентичности
  устройства, бейджи состояния у сущности).

Идентичность Routevane внутри стандарта: акцент — не холодный голубой, а
сигнальный зелёный маршрута (наследник текущего #175f46, осветлённый для
тёмного грунта, ориентир #4fae7f; финальные значения — на этапе токенов);
второй фирменный ход — моноширинная «трасса» маршрута `сервис → артефакт →
устройство` как повторяющийся текстовый паттерн заголовков разделов.
Тема: тёмная по умолчанию (вечерняя сцена использования), светлая — через
`prefers-color-scheme` + переключатель; обе от одних семантических токенов.

## 4. Структура: три экрана и два режима

Ответ на подтверждённую проблему «шесть задач в одном скролле».

**Каркас.** Узкий верхний бар (chrome-зона): слева имя продукта, по центру —
три раздела-шага с состоянием, справа — глобальный статус-индикатор
(точка + текст: «Роутер обновился 12 мин назад» / «Роутер ещё не обращался»)
и переключатель режима «Просто / Подробно». Один `<main>` на экран, один
видимый заголовок страницы.

**Экран 1 — Сборка** (`/`). Каталог устройств и сервисов. Простой режим:
крупные карточки-чекбоксы сервисов с категориями, селектор устройства с
подсказкой «как узнать мой роутер», одна primary-кнопка «Собрать маршрут»
с inline-прогрессом стадий (профиль → DNS → проверка → публикация) прямо в
кнопке/строке под ней — без отдельного экрана ожидания. Подробный режим
добавляет: покрытие по каждому сервису до сборки, reason-коды, лимит цели
(«Keenetic: до 1024 строк»).

**Экран 2 — Артефакт** (`/artifact/{id}`). Паспорт результата:
- факты (сервисы, устройство, время, «Проверено · 38 правил»);
- **содержимое файла дословно**: моно-`<pre>` с реальными строками
  `route ADD…`, счётчик строк, разбивка по сервисам («YouTube — 24,
  Discord — 14»), кнопка «Скопировать» (закрывает подтверждённый дефект
  «файл никуда не выводится»; технически — fetch того же
  `GET /v1/artifacts/{id}`);
- блок секрета: ссылка подписки с маской, «Показать» / «Скопировать»,
  предупреждение о невосстановимости остаётся видимым после раскрытия;
  regenerate — в бэклог бэкенда;
- скачивание файла (имя формата — из данных цели, как сейчас);
- предупреждение о покрытии — один блок, с именами доменов и раскрытием
  диагностики; постоянные ограничения цели — информационный тон, не янтарная
  тревога;
- Подробный режим: диагностика-леджер (правило, значение, TTL, происхождение,
  причина — выровненные строки, моно-метаданные), формат/рендерер, снапшот.
URL адресуем: F5 и возврат по ссылке восстанавливают экран (артефакты
иммутабельны, `GET /v1/profiles/{id}` уже отдаёт `latest_artifact_id`;
не восстанавливается только секрет — экран честно говорит об этом).

**Экран 3 — Доставка** (`/artifact/{id}/deploy`). Два пути табами:
«Автоматически» (адрес → проверка → эхо устройства «Keenetic Giga, 4.x» →
план изменений → применение → аудит шагов с откатом) и «Вручную»
(скачивание + пошаговая инструкция цели + подписка). Ошибки — только через
словарь, рядом с виновным полем; адрес/аккаунт/интерфейс запоминаются в
сессии; интерфейс устройства — выбор из списка, который вернул probe.

**Простой режим** ведёт по шагам линейно (1 → 2 → 3, следующий шаг
подсвечен, будущие — приглушены); **Подробный** — все три раздела доступны
сразу, плотность выше, диагностика раскрыта. Режим — предпочтение в
localStorage, не отдельная вёрстка.

## 5. Состояния и диапазоны

Грамматика состояний экрана:
`loading / ready / empty / degraded / error` — каждый экран реализует все
пять одним компонентом «что отсутствует, почему, следующее действие».
Ключевые случаи: каталог недоступен (retry), сборка упала (предыдущий
артефакт сохранён — сказать явно), частичное покрытие (число, имена,
следствие, действие), деградировавший источник (транзиент, янтарный),
устройство не поддерживает авто-применение (переключить на «Вручную»),
роутер ни разу не забрал подписку (главный живой статус). Диапазоны:
1–10 сервисов, 14–1024 правил, артефакт 2–60 КБ, 1–3 устройства.

## 6. Взаимодействие и вёрстка

- **Ноль CLS по вине UI**: место под сообщения, план и статусы
  зарезервировано; фоновая догрузка никогда не удаляет/не пересоздаёт
  узлы (подтверждённый дефект: снапшот-фетч пересоздавал панель применения,
  CLS 0.21). Обновление данных — на месте, без blanking.
- Статус — примитив с одним владельцем: карта «измерение × состояние →
  тон + метка», точка или 3px-кромка, цвет всегда продублирован текстом.
- Фокус управляем: переходы шагов переносят фокус на заголовок экрана;
  раскрытие секрета не роняет фокус; Esc закрывает раскрытия.
- Копирование подтверждается у кнопки, не в другом углу.
- Клавиатура: полный путь Tab-ом, видимый фокус ≥2px/3:1.
- Токены: два уровня (примитивы + семантические роли), шкала шрифтов
  12/13/14/16/18/24, моно-роль для URL, id, IP/CIDR, содержимого артефакта.
- SSE для статуса подписки/применения без polling.

## 7. Ограничения и открытые решения

Обязательные ограничения: один Go-бинарь, CSP `'self'`, без внешних шрифтов
и ресурсов; Nuxt/Vue в `web/src`; терминология продукта; WCAG 2.2 AA-чеклист
из PRODUCT.md; RU/EN без хардкода копии.

Требуется от бэкенда (бэклог, не блокирует вёрстку экранов 1–3):
1. `last_polled_at` подписки — для живого статуса роутера (сильнейшее
   отличие от всех RU-конкурентов);
2. regenerate ссылки подписки с инвалидацией старой;
3. probe возвращает список интерфейсов устройства;
4. (позже, для истории) списочный `GET /v1/artifacts?profile=…`.

Открытые решения, которые исполнитель не изобретает сам: точные значения
палитры/токенов (фиксируются при реализации от нейтральных референсов),
шрифт (системный стек или Inter локально — решить по CSP и размеру),
состав светлой темы, формулировки копии — через словарь i18n с ревью.

Анти-цели: никакого сайдбар-rail и Global/Project-скоупов (такой масштаб
не нужен одностраничному продукту), никакого скевоморфизма и метафор,
никаких заливных статус-бейджей, никаких самообъясняющих абзацев под полями.
